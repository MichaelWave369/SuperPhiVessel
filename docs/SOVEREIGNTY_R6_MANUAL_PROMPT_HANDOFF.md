# Sovereignty R6 · Operator-controlled local prompt handoff

**Status:** browser-local staging of text into **existing** Ollama/PhiServe one-shot editors. This is **not** automatic provider switching, inference, a new gateway, a canonical runtime connection, model restoration, or an execution grant.

## User flow

1. Launch the existing Windows Local Console. The default `Start-Local-Vessie.cmd` stays read-only. Inference still requires the separate `Start-Local-Trial.cmd` or `Start-PhiServe-Desk.cmd` entrypoint, chosen at process startup. Both modes cannot be enabled in the same console process.
2. Under **Sovereignty · Provider Independence**, click **Read local console startup mode**. This calls the existing authenticated `/api/status` on `127.0.0.1:8791`, and does **not** query Ollama, PhiServe or a cloud endpoint.
3. Choose a planning preference: No inference, local Ollama or local PhiServe. For Ollama, use the existing **Discover my local models** scan first. A cloud-tagged model or unknown-weight entry is never eligible for a local trial. For PhiServe, process startup mode must be enabled; the handoff does not claim that the local daemon or model has been discovered.
4. Enter a short prompt (at most 2,000 characters, no secrets), then explicitly click **Copy prompt into selected local editor**. Nothing runs.
5. Ollama: the prompt appears in **One-shot local inference trial**. Any previous model choice and fixed-prompt protocol are cleared, old human review/receipt is invalidated, and per-request approval remains unchecked. Choose a local-size-reported model, approve once, then separately confirm the existing trial action.
6. PhiServe: the prompt appears in **Φ PhiServe Model Desk**. The previous alias selection and approval are cleared; its existing change handler resets prior verified draft/review state. Click **Discover local PhiServe models**, choose an alias, approve once, and separately click the existing Generate button.

The input in the staging panel is cleared after a successful copy, reducing unintended duplicate display. The destination editor still contains the text until manually cleared or the tab is closed. The model providers may have their own logging/retention behavior if a later request is approved.

## Boundaries

- This does not move a live model session, conversation history, PV-MEM, identity or credentials between providers.
- No `POST` is generated by the new stage button and no inference API is contacted until the existing separately guarded controls are activated.
- A provider outage, unavailable server status, cloud-only Ollama inventory, disabled local inference startup or invalid prompt yields **HELD** or **REFUSED**, never auto-fallback.
- The existing Ollama server re-probes weights immediately before an approved trial. PhiServe's separate authenticated backend verifies registered aliases and active mode. Their server-side constraints are unchanged.
- No permission, route, grant, lease, memory admission or canonical Vessie runtime mutation is performed or implied.
- The staged prompt is handled in browser memory as UI state, not saved to files or a database by this change. Browser internals/OS memory are not independently attested.
- Only the existing `/api/status` loopback GET was added to the observer panel by an explicit operator click. The page's existing Ollama and PhiServe controls retain their independent behavior.
- The hosted React cockpit is separate; it does not receive this prompt or become a local model controller.
