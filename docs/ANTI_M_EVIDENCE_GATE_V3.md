# Anti-M Evidence Gate V3 · local shadow assessment

Status: **proposed / non-authoritative**. This feature is a separate, deterministic policy evaluator in \`apps/vessie-web/src/evidence-gate.mjs\`, exposed by a browser-only shadow bench alongside Anti-M's completion console. It does not alter \`anti-m.mjs\`, the canonical runtime, CraneFly routes, BrainC memory, or any executor.

## Original observed motivation (October 17, 2026)

In a synthetic network incident with a reported switch outage but **no telemetry and no known business impact**, local \`granite4.2:8b\` suggested low risk and \`qwen3.5:9b\` suggested high risk. Both recommendations violated the test's explicit policy: if impact evidence is absent, severity must be \`undetermined\`. The original PowerShell V1 and V2 rules rejected those recommendations, and V2's seven controls passed on the operator's PC.

This PR moves the narrow policy into a reusable, testable JavaScript function. It does **not** claim the models are generally unsafe, that the sample validates network diagnoses, or that this bench independently proves any incident happened.

## Interface

\`evaluateEvidenceGate(proposal, context)\` accepts:

- A model proposal with exact fields: \`status\`, \`risk\`, \`confidence\`, \`evidence\` (source IDs), and \`action\`.
- Caller-supplied source records with exact \`id\`, \`kind\`, \`provenance\`, \`statement\`, \`reference\`, \`riskLevel\`, and \`observedConnectivity\` fields.

Source records are **not to be generated by the proposing model**. The caller is responsible for obtaining and checking them before marking anything \`VERIFIED\`; the library merely checks shape and reference presence, not identity, signatures, real-world truth, or the content at a URL.

The gate rejects invalid input shapes, unknown/duplicate evidence IDs, missing citations of the report, unsupported verified-down/healthy claims, conflicting verified sources, non-undetermined severity without verified impact, severity mismatches, and uncited impact claims. Without cited connectivity observations, diagnostic confidence must be low.

An \`ALLOW_ASSESSMENT_ONLY\` result means *this narrow set of rules found no violation*. It grants **no** permission, verified DONE, medical/safety judgment, or independent execution attestation. An \`action\` string is a descriptive model proposal, never an instruction executed by this component.

## Browser demo

Open the Anti-M tab and scroll to **Evidence Gate V3 · Shadow Bench**. The initial JSON is intentionally a negative control with \`"risk":"high"\` and the only source being a reported switch outage. Click **Evaluate proposal** to see \`REJECT\` and \`UNSUPPORTED_SEVERITY\`. Click **Load conservative control**, then evaluate again to see \`ALLOW_ASSESSMENT_ONLY\`, not a grant.

The page never calls Ollama or any remote API for this bench, does not import sources or outcomes into the Anti-M ledger, does not persist inputs between reloads, and cannot perform actions.

## Verification

Run from \`apps/vessie-web\`:

\`\`\`sh
npm test
npm run build
\`\`\`

The new \`tests/evidence-gate.test.mjs\` covers all seven previous V2 controls (adapted to exact JSON shape), the two observed local model policy violations, incorrect severity despite a supplied impact source, non-cited impact, fabricated source identifiers, unsupported status claims, contradictory sources, false source-reference shape, duplicate IDs, and invalid authority fields.

## Follow-up boundaries

A future trusted-source adapter must validate source custody independently. Any permanent evidence receipt must preserve both the proposal and rejected verdict in an append-only ledger with explicit trust labels. A future live router or executor must separately enforce operator approval. **None of those features ships in V3.**
