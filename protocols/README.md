# Protocols

Governed contracts and protocol specifications belong here.

Examples include authority, evidence, promotion, interaction-proof, work-envelope, receipt, bridge, and distributed-memory contracts.

Protocol documents should state:

- inputs and outputs
- authority boundary
- provenance/evidence behavior
- failure semantics
- deterministic invariants
- version identifier

A protocol document does not imply the protocol is wired into the current runtime.
